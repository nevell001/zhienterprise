# 模块化建站架构方案（Module Builder）

> 版本 v1.0 ｜ 状态：**待评审** ｜ 取代「5 套固定行业模板」的实现思路
> 依据：`docs/design/企业官网UI-UX架构方案.md`（模块清单与规范基线）

---

## 一、问题定义（为什么当前实现不可接受）

当前实现（Phase 3.1~3.2）的"模板"是**运行时皮肤 + 文案包**：`site_template` 决定
一套写死在代码里的文案/母题，页面结构与模块顺序硬编码在 `EnterpriseHome.vue`。
对照设计方案逐项检查，存在四个结构性缺陷：

| # | 缺陷 | 设计方案要求 |
|---|---|---|
| 1 | 导航菜单硬编码（5 项写死在组件里） | 导航是站点信息架构，应可后台管理 |
| 2 | 首页模块顺序/开关/数量写死（10 模块固定排列） | 页面由模块组成，应可排序/开关/增删 |
| 3 | 内容与模板耦合（切行业模板=整包换文案，管理员无法只改一句 Hero） | 内容归内容（后台维护），模板归模板（初始示范） |
| 4 | 只有首页可组装，其他页面结构固定 | 页面管理应支持自定义组装 |

**根因**：把"模板"实现成了运行时皮肤，而建站系统里"模板"的正确语义是
**一键导入的预置数据包**——导入之后，一切都是普通数据，随便改。

## 二、目标架构

### 2.1 三层模型

```
┌─────────────────────────────────────────────────┐
│ 模板包（Template Pack，预置数据，仅导入用）       │
│  = 页面集 + 模块配置 + 导航 + 设置的初始 JSON     │
│  现有 5 套行业模板 → 改造为 5 个模板包            │
├─────────────────────────────────────────────────┤
│ 数据层（全部可编辑）                              │
│  ├ site_nav_item      导航项（头部/页脚，两级）    │
│  ├ site_page          页面（含模块列表，见 2.3）  │
│  └ zhi_setting        全局键（主题变量/联系方式…）│
├─────────────────────────────────────────────────┤
│ 渲染层（代码，稳定）                              │
│  └ SectionRenderer → 模块组件注册表（按 type 分发）│
└─────────────────────────────────────────────────┘
```

### 2.2 模块（Section）类型目录

与设计方案 §1.3 模块清单一一对应，每个 type 对应一个已抽出的 Vue 组件：

| type | 模块 | 数据形态（config JSON） | 数据来源 |
|---|---|---|---|
| `hero` | 首屏 Hero | eyebrow/title/subtitle/ctaPrimary/ctaSecondary/image | 内容型 |
| `metrics` | 信任指标条 | items[{value,label}] | 内容型 |
| `biz-cards` | 核心业务两卡 | cardOne/cardTwo{title,desc} + 列表引用 | 混合（+business 文章） |
| `solutions` | 解决方案精选 | items[{title,desc}] + 链接 | 内容型 |
| `outcomes` | 数据成果 | items[{mark,suffix,label}] | 内容型 |
| `logos` | 客户 Logo 墙 | 来源固定友链，config 控制 count | 引用型（友链） |
| `news` | 新闻动态 | count / categoryKey | 引用型（news 文章） |
| `cases` | 客户案例 | count / categoryKey | 引用型（case 文章） |
| `cta` | 转化区块 | title/subtitle/buttons | 内容型 |
| `rich-text` | 富文本区块 | content(HTML，经消毒) | 内容型 |
| `faq` | FAQ 手风琴 | items[{q,a}] | 内容型（+FAQPage JSON-LD） |
| `channels` | 分渠道咨询 | items[{name,desc}] | 内容型 |
| `honors` | 荣誉墙 | items[{name,issuer,year,cat}] | 内容型 |
| `history` | 发展历程 | stages[{range,name,theme,events[]}] | 内容型 |
| `contact-info` | 联系信息卡 | 引用设置键电话/邮箱/地址 | 引用型（设置） |

> 关键点：`hero` 等文案类模块全部成为**普通数据**——管理员在后台改 Hero 标题，
> 与"选了哪个行业模板"无关。行业模板只是**初始值的来源**。

### 2.3 数据模型

**页面表扩展**（复用 `zhi_page`，不新建页面表）：

```sql
ALTER TABLE `zhi_page`
  ADD COLUMN `page_type` varchar(20) NOT NULL DEFAULT 'richtext'
    COMMENT '页面类型：richtext 富文本页 builder 模块组装页',
  ADD COLUMN `sections` json DEFAULT NULL
    COMMENT '模块列表（builder 页）：[{type,config,visible}]，顺序即渲染顺序';
```

- 首页是特殊页：`slug='home'` 的 builder 页（`home_page_slug` 机制退役，
  改为 `home_page_id` 指向首页；或保留 slug 机制，`home_page_slug='home'`）。
- 现有富文本页（about 等）升级为「富文本 + 可选挂模块」混合页：
  `page_type='richtext'` 保持不变；builder 页不再有 content 字段语义。

**导航表**（新建）：

```sql
CREATE TABLE `site_nav_item` (
  `id`        bigint NOT NULL AUTO_INCREMENT,
  `location`  varchar(20) NOT NULL COMMENT 'header / footer',
  `parent_id` bigint DEFAULT 0 COMMENT '0=顶级，否则为二级下拉项',
  `label`     varchar(50) NOT NULL,
  `link_type` varchar(20) NOT NULL DEFAULT 'path' COMMENT 'path 站内路径 / page 页面 / url 外链 / anchor 锚点',
  `link_value` varchar(255) NOT NULL,
  `sort`      int DEFAULT 0,
  `visible`   tinyint DEFAULT 1,
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`), KEY `idx_loc_sort` (`location`, `sort`)
) COMMENT='站点导航项（企业官网头部/页脚菜单）';
```

CTA 按钮（"咨询合作"）= `location='header'` 且 `link_type='cta'` 的特殊项，可改文案与链接。

**公开接口**（匿名，短缓存）：
- `GET /api/nav?location=header|footer` → 导航树
- `GET /api/page/{slug}` → 扩展返回 `pageType` 与 `sections[]`（builder 页）
- 首页：`GET /api/page/home`（特殊 slug 直取）

**管理接口**（权限 `site:nav:*`、复用 `site:page:*`）：
- 导航 CRUD + 排序（拖拽后批量提交顺序）
- 页面管理升级：builder 页的模块列表编辑（增删/排序/开关/编辑抽屉）

### 2.4 前端渲染架构

```
views/site/page-renderer.vue        ← builder 页统一入口（按 sections 循环）
  └─ <SectionRenderer :type :config />
       ├─ sections/hero/index.vue        （读 config + 模板视觉变量）
       ├─ sections/metrics/index.vue
       ├─ sections/business-cards/index.vue
       ├─ sections/{solutions|outcomes|logos|news|cases|cta|
       │             rich-text|faq|channels|honors|history|contact-info}/...
```

- **模块组件注册表** `sections/registry.ts`：`Record<sectionType, Component>`，
  未知 type 渲染空（前向兼容：新模块类型上线旧数据不受影响）。
- **视觉层不变**：`.tpl-site/.tpl-xxx` 变量体系继续作为全局视觉预设
  （5 套主题 = 5 组变量），与内容/模块彻底解耦——这就是"模板"的最终定位：
  **视觉预设（变量）+ 内容预置包（数据）**，二者都可换、可改、可混搭。
- **滚动入场**：`useScrollReveal` 已支持 MutationObserver 接管动态插入节点，
  模块化渲染天然兼容。

### 2.5 管理后台交互

**「页面管理」升级为建站管理器**：

```
页面列表
├─ 富文本页（现状不变）
└─ 模块组装页（builder）
     ├─ [添加模块] → 模块类型选择器（图标 + 名称 + 说明）
     ├─ 模块列表：拖拽排序（sort）｜眼睛开关（visible）｜[编辑]｜[删除]
     └─ [编辑] → 右侧抽屉（480px）：按模块类型渲染对应配置表单
          （表单结构 = 模块 config JSON Schema 的 UI 映射，先做手写表单，
           每个模块一个编辑组件）
```

**「导航管理」新页**（站点管理下）：
- 头部/页脚两个 Tab；顶级项列表（拖拽排序）+ 展开二级项
- 行内编辑：标签 / 链接类型（站内路径·页面·外链·锚点）/ 链接值 / 可见
- CTA 按钮项特殊标记
- 变更即时生效（导航接口短缓存失效）

**「界面主题」收敛为纯视觉**：外观模式 + 主题颜色 + 行业视觉预设
（`.tpl-xxx` 变量组，改名"行业配色"，不再携带任何文案）。

### 2.6 行业模板的新语义：预置数据包

5 套行业模板改造为 **Template Pack JSON**（`migrations/templates/t-consult.json` 等）：

```json
{
  "id": "consult",
  "name": "管理咨询",
  "theme": { "tplClass": "tpl-consult" },
  "pages": {
    "home": { "sections": [ {"type":"hero","config":{...文案…}}, ... ] },
    "about": { "sections": [...] }
  },
  "nav": { "header": [...], "footer": [...] },
  "settings": { "business_label": "咨询中心", ... }
}
```

- 后台「界面主题 → 行业模板」按钮 = **导入包**：写入 pages/nav/settings
  （覆盖确认对话框：将覆盖首页与导航的当前内容）。
- 导入后全部是普通数据，管理员随意改；再切另一包 = 再导入一次。
- 价值：新增行业模板 = 写一个 JSON 包（运营可做），不需要发版。

## 三、迁移路径（存量兼容）

| 存量 | 迁移 |
|---|---|
| `home_layout=business` + EnterpriseHome | 首次启动迁移：生成 slug='home' 的 builder 页，按现有顺序写入 14 个模块配置；`home_layout` 退役 |
| 7 个内容设置键（site_metrics 等） | 值迁移进对应模块 config；键保留一个版本后废弃 |
| `home_page_slug` 自定义页接管 | 保留：rich-text 页仍可被设为首页（优先级高于 builder 首页） |
| 行业模板 site_template | 值映射为"最近导入的包 id"；不再影响运行时渲染 |
| 短路径路由 / business / news 等 | 不变（页面路由与组装解耦） |

迁移用幂等 SQL + 启动守卫（参照 `99_rename_blog_to_zhi.sql` 的演练方式）。

## 五、风险与取舍

1. **sections JSON 无外键约束**：模块 config 由前端表单保证形状 + 渲染端容错
   （config 解析失败渲染占位，不白屏）；不引入 JSON Schema 校验中间件（过度设计）。
2. **首页性能**：builder 页比硬编码多一次页面接口请求 → 页面接口加短缓存
   （参照站点设置 600s 模式），且模块内引用型数据（文章/友链）本就异步。
3. **SEO**：模块页仍是 SSR-less 客户端渲染——与现状一致；设计方案 §6.1 的
   "HTML 直出"属长期项（预渲染/SSR），不在本方案范围。
4. **旧 EnterpriseHome/行业模板文案包**：M1 迁移完成后删除，避免双轨。
